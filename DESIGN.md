# The Accelerate design system

This is the visual system used across Accelerate's work — black, crimson, white; condensed
uppercase for display; monospace wherever the interface is quoting a machine. It is derived from
the club's poster and event artwork, and this repository is the reference implementation of it on
the web.

Read this before changing `style.css`.

## Colour

Six tokens. They are defined once at the top of `style.css` and used everywhere; no component
hard-codes a colour.

| Token | Value | Role | Contrast on `--ink` |
|---|---|---|---|
| `--ink` | `#0a0a0a` | The page. Near-black, not pure black — pure black against a bright crimson is harsher than it needs to be. | — |
| `--ink-raised` | `#131317` | Cards, chips, inline code | — |
| `--ink-hover` | `#1b1b21` | Card hover | — |
| `--paper` | `#ffffff` | Primary text | 19.8:1 |
| `--paper-dim` | `#9ca0a6` | Secondary text, metadata, navigation | 7.5:1 |
| `--flare` | `#ee3b44` | The accent. Emphasis, links, active state, the rocket's red. | 5.0:1 |
| `--flare-bright` | `#ff5c63` | Hover and focus | 6.6:1 |

Every pair clears **WCAG 2.1 AA** (4.5:1 for body text, 3:1 for large text), which Article III.2 of
the Constitution requires. **If you change a colour, measure it again** and update the comment next
to it. The [WebAIM contrast checker](https://webaim.org/resources/contrastchecker/) is the tool the
club's contributing guide points at.

### It is dark, and only dark

There is no light variant. The identity is black-and-crimson; a white version would read as a
different project. `color-scheme: dark` is declared so form controls and scrollbars follow.

### Using the accent

Crimson is a spotlight, not a fill. In practice that means:

- **The sentence turns crimson at the point it makes a claim.** The poster does this — *"Every
  launch code is a secret. **Ours aren't.**"* On the site it's the `.accent` span in an `<h1>`.
- **One accent per view.** If two things are crimson, neither is emphasised.
- **State, not decoration.** A hover, a focus ring, an empty count that wants filling.

Large crimson areas are wrong. There is no crimson background anywhere in this system except the
skip link, which is deliberately loud because it should be impossible to miss.

## Type

Three voices, and the rule for which to use is about *who is speaking*.

| Voice | Face | Where |
|---|---|---|
| **Display** | Anton, uppercase, `line-height: 0.98` | `h1`, `h2`, card titles, the wordmark. Loud, condensed, tightly set. |
| **Reading** | Space Grotesk, 400–700 | Body copy, ledes, descriptions. Anything a person wrote for a person. |
| **Machine** | JetBrains Mono | Terminal motifs, navigation, breadcrumbs, subject codes, counts, the footer. Anything the interface is quoting from a file, a path, or a shell. |

The monospace rule is the one that carries the identity. Paths, counts, branch codes and nav labels
are all things a machine would print, so they are set as though a machine printed them —
`pyq-archive`, not "PYQ Archive".

Fonts are self-hosted under `assets/fonts/` and are all SIL OFL 1.1. See
[`assets/fonts/README.md`](assets/fonts/README.md). Do not add a Google Fonts `<link>` — the
no-external-requests rule is deliberate.

## Motifs

Four, all cheap and all optional. Use them sparingly; the archive has to stay readable.

### The prompt

A shell prompt as an eyebrow above a heading:

```html
<p class="prompt">find ./pyq -name "*.pdf"</p>
```

The `$ ` is generated by CSS, not written into the markup, so a screen reader reads the label
rather than the prompt character. Write something that is plausibly the command that got you to
this screen.

### The trajectory

The poster's flight path, flattened into a divider with one lit node:

```html
<hr class="trajectory" />
```

One per page at most. It marks the break between the pitch and the content.

### The slash

A crimson bar before the wordmark — the rocket's trail reduced to a mark. It's a `::before` on the
site title; there is no image to load and nothing to give alt text to.

### The starfield

Drawn with `radial-gradient`s on `body`, fixed so it sits behind the content rather than scrolling.
A handful of dots at low opacity plus one wide crimson bloom in the top right. No network request,
no `<img>`, nothing to describe.

## Accessibility rules that are part of the system

These are not optional polish; they are the reason the system passes review.

- **Focus is always visible.** `:focus-visible` gets a 2px `--flare-bright` ring at 3px offset.
  Never `outline: none` on something a keyboard can reach. The single exception is
  `main[tabindex="-1"]`, which is a programmatic focus target and not a Tab stop — the rule
  documents why.
- **Contrast is measured, not eyeballed.** See the table above.
- **Motion respects `prefers-reduced-motion`.** All transitions collapse to near-zero.
- **Link text stands alone.** A link reading "MTE 2024" is meaningless in a screen reader's link
  list, so paper links carry a fuller `aria-label`. If you change what a link displays, change its
  accessible name too.
- **Decoration is never content.** The prompt `$`, the slash, the starfield and the trajectory are
  all CSS. Nothing that carries meaning is drawn with a pseudo-element.

## Reusing this in another club repo

Copy `style.css` and `assets/fonts/`. The tokens, the three-voice type rule and the four motifs are
the system; everything below the `--- Card grids ---` comment is this project's components and can
be dropped.
